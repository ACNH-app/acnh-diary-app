# 모동숲 다이어리 모바일 앱 요구사항 정의서

문서 상태: Draft v1.8
최종 수정일: 2026-08-30
대상: React Native + Expo SDK 57 + Expo Router + TypeScript 기반 모바일 앱
기준 데이터: 저장소의 `dataset/app-ready/` 앱용 데이터셋. 주민은 417명 기준이다.

## 1. 문서 개요

### 1.1 목적

본 문서는 모동숲 다이어리 모바일 앱의 기능·데이터·품질 요구사항을 정의한다. 모바일 앱은 웹 서버나 로그인 없이 기기 내 SQLite에 사용자 기록을 저장하며, 앱을 종료하거나 네트워크가 없어도 핵심 기능을 사용할 수 있어야 한다.

### 1.2 모바일 앱 범위

- 온보딩과 여러 섬 관리
- 오늘 화면의 날짜 기반 정보와 일일 기록
- 주민 검색·상세·상태 및 이력 관리
- 곤충·물고기·해산물·화석·미술품 도감과 수집·기증 관리
- 모바일 기기에서의 JSON 백업·복원
- 기준 데이터별 원 출처·기준 데이터 버전·오픈소스 라이선스 고지
- 카탈로그 11개 분류의 오프라인 조회·검색·필터·정렬·보유 기록
- 공략은 내비게이션 자리와 확장 계약만 제공하고 후속 단계에서 구현
- 현재 출시 검증 대상은 iOS이며 Android는 후속 플랫폼으로 둔다.

### 1.3 제외 범위

- 웹앱과의 자동 동기화
- 모바일 로그인 및 서버 계정
- 날씨 예보·MeteoNook 연동
- 무 가격 계산기
- 요일별·주간 루틴
- 복수 주민대표

## 2. 제품 개요

### 2.1 제품 정의

모여봐요 동물의 숲 플레이어가 여러 섬의 주민·도감·일일 루틴을 기록하고, 현재 게임 날짜와 시간에 맞는 정보를 오프라인에서 확인하는 개인용 모바일 앱이다.

### 2.2 핵심 원칙

1. 모든 사용자 기록은 `islandId`로 구분한다.
2. 기준 데이터와 사용자 기록을 분리한다.
3. 네트워크 없이 오늘·주민·도감의 조회와 기록 변경이 가능해야 한다.
4. 기록 변경은 즉시 저장하고 앱 재실행 후에도 유지한다.
5. 색상만으로 상태를 구분하지 않고 아이콘·텍스트·체크 상태를 함께 제공한다.
6. 기준 데이터가 갱신되어도 사용자의 기록은 유지한다.

## 3. 정보 구조와 내비게이션

### 3.0 라우팅 결정

앱 라우팅은 Expo Router를 사용한다. `acnh-diary-mobile/src/app/`의 파일과 폴더가 화면 경로를 정의하고, `_layout.tsx`에서 Stack·Tab·Modal 레이아웃을 구성한다. Expo Router가 내부적으로 React Navigation을 사용하더라도 앱 코드에서 React Navigation navigator를 별도로 구성하지 않는다.

앱 번들 진입점은 `expo-router/entry`로 고정한다. `App.tsx`와 사용자 정의 `index.ts`는 앱 라우팅 진입점으로 사용하지 않는다.

### 3.1 최초 진입

1. 스플래시 화면
2. 기존 섬이 없으면 온보딩
3. 기존 섬이 있으면 마지막 활성 섬 기준 오늘 화면

### 3.2 하단 내비게이션

1. 오늘
2. 주민
3. 도감
4. 카탈로그
5. 공략

오늘·주민·도감·카탈로그는 모바일 MVP에서 구현한다. 공략은 비활성 또는 준비 중 상태로 표시할 수 있다. 현재는 iOS에서만 출시 기준을 검증하고 Android는 후속 플랫폼으로 둔다.

### 3.3 섬 관리 메뉴

오늘 화면의 메뉴 버튼에서 다음 기능을 제공한다.

- 활성 섬 정보 요약
- 섬 변경
- 섬 추가
- 섬 정보 수정
- 섬 삭제
- 주민대표 정보 확인·수정
- 앱 설정 및 데이터 출처·라이선스
- 백업·복원

마지막 섬은 삭제할 수 없다.

## 4. 기능 요구사항

### 4.1 온보딩 및 섬 관리

- **MOB-ISL-001**: 사용자는 섬 이름, 대표과일, 자생꽃, 반구, 시간대를 입력할 수 있어야 한다.
- **MOB-ISL-002**: 사용자는 주민대표 이름과 생일을 입력할 수 있어야 한다.
- **MOB-ISL-003**: 섬 이름과 주민대표 이름은 최대 10자로 제한한다.
- **MOB-ISL-008**: 첫 섬 생성은 섬 정보, 주민대표 정보, 기본 루틴 생성을 하나의 저장 작업으로 처리하고 생성한 섬을 활성 섬으로 지정한다.
- **MOB-ISL-004**: 섬을 여러 개 등록하고 활성 섬을 변경할 수 있어야 한다.
- **MOB-ISL-005**: 활성 섬을 변경하면 오늘·주민·도감·루틴·NPC 기록을 선택한 섬 기준으로 다시 표시해야 한다.
- **MOB-ISL-006**: 섬별 사용자 기록은 다른 섬의 기록과 섞여 표시되지 않아야 한다.
- **MOB-ISL-007**: 마지막 섬 삭제는 차단하고 안내 메시지를 표시해야 한다.
- **MOB-ISL-009**: 주민대표 생일은 월·일을 입력받고 유효한 날짜만 저장하며, 섬 관리 화면에서 수정할 수 있어야 한다.

### 4.2 오늘 화면

- **MOB-TOD-001**: 기본 날짜와 시간은 기기 시각을 사용한다.
- **MOB-TOD-002**: 게임 날짜의 경계는 오전 5시로 적용한다. 오전 5시 이전에는 전날을 게임 날짜로 계산한다.
- **MOB-TOD-003**: 사용자는 날짜 선택기로 기준 날짜를 수동 변경할 수 있어야 한다.
- **MOB-TOD-004**: 수동 날짜를 해제하면 기기 시각과 오전 5시 경계로 복귀한다.
- **MOB-TOD-005**: 현재 계절·이벤트·시즌 레시피·별자리·너굴쇼핑 등 날짜 기반 정보를 표시한다.
- **MOB-TOD-006**: 날짜와 시간에 따라 현재 잡을 수 있는 곤충·물고기·해산물을 표시한다.
- **MOB-TOD-007**: 현재 출현 생물에는 이름, 출현 위치, 채집 여부·박물관 기증 여부를 표시한다.
- **MOB-TOD-008**: 루틴은 기본 루틴과 사용자가 추가한 루틴으로 구성한다.
- **MOB-TOD-009**: MVP 루틴 반복 주기는 매일만 지원한다.
- **MOB-TOD-010**: 루틴 미완료 이미지는 회색, 완료 이미지는 원래 색상으로 표시하고 체크 상태를 함께 제공한다.
- **MOB-TOD-011**: 루틴의 현재 횟수와 목표 횟수를 기록할 수 있어야 한다.
- **MOB-TOD-012**: 루틴 이름·목표 횟수·표시 순서의 수정과 삭제는 오늘 이후에 적용한다. 과거 날짜의 정의와 로그는 보존한다.
- **MOB-TOD-013**: 과거 날짜에서는 해당 날짜의 완료 상태만 수정할 수 있다.
- **MOB-TOD-014**: 최근 방문 NPC는 현재 날짜가 포함된 월요일~일요일 주간으로 표시한다.
- **MOB-TOD-015**: 토요일 K.K., 일요일 무파니는 미기록 상태에서 기본값으로 표시하고 사용자가 변경할 수 있어야 한다.
- **MOB-TOD-016**: 요일을 선택하면 NPC 선택 화면을 열고, 주간 초기화 시 해당 주의 기록만 삭제한다.
- **MOB-TOD-017**: 주간·월간 캘린더에서 주민 생일과 이벤트를 표시한다.
- **MOB-TOD-018**: 최근 방문 NPC는 NPC 이름과 로컬 이미지 자산을 표시한다. 해당 NPC 자산이 앱 데이터셋에 없는 동안에는 이름을 잃지 않는 접근성 가능한 대체 표시를 사용한다.
- **MOB-TOD-019**: 현재 출현 생물 중 전월에는 출현하지 않았고 현재 게임 월에 출현하기 시작한 생물에 `이번 달 신규` 표시를 제공한다.
- **MOB-TOD-020**: 현재 출현 생물 중 다음 게임 월에는 출현하지 않는 생물에 `이번 달 종료` 표시를 제공한다.

기존 기획에 남아 있는 `출현시간/월???`, `다가오는 이벤트… 이벤트의 범위?` 등의 물음표는 별도 결정 전까지 원문 의미를 유지한다.

- **MOB-VIL-012**: 주민 액자 사진과 포스터의 이미지, 가격, 획득방법, 보유 여부를 표시한다.
- **MOB-VIL-013**: 액자 사진 보유 상태는 주민의 액자 선물 받은 상태와 연동한다.
- **MOB-VIL-014**: 주민 카드를 선택하면 바텀시트가 아닌 독립 상세 페이지로 이동하며, 공통 상단 바의 뒤로가기·햄버거 메뉴와 상세 스크롤을 제공한다.

### 4.4 도감

#### 4.4.1 도감 홈과 목록

- **MOB-ENC-001**: 도감 홈에서 곤충, 물고기, 해산물, 화석, 미술품을 선택할 수 있어야 한다.
- **MOB-ENC-002**: 항목 선택 시 해당 목록 화면으로 이동하고, 카드 선택 시 모바일 상세 화면으로 이동한다.
- **MOB-ENC-003**: 목록 화면에 검색창과 카테고리 구분, 필터, 정렬을 제공한다.
- **MOB-ENC-004**: 곤충·물고기·해산물은 채집·기증 여부, 화석은 보유·기증 여부, 미술품은 기증·진품 보유·가품 보유 여부를 복수 선택 가능한 필터 칩으로 제공한다.
- **MOB-ENC-005**: 필터 칩은 조건을 조합해 검색할 수 있어야 한다.
- **MOB-ENC-006**: 전체 조회에서 곤충·물고기·해산물 카드는 번호순 기준 5개씩, 화석·미술품 카드는 2개씩 표시한다.
- **MOB-ENC-007**: 생물 카드에는 채집 아이콘과 박물관 기증 아이콘을, 화석 카드에는 보유 아이콘과 박물관 기증 아이콘을, 미술품 카드에는 진품 보유·가품 보유·박물관 기증 아이콘을 표시한다.
- **MOB-ENC-008**: 카드 아이콘을 눌러 상태를 즉시 변경하고 변경 결과를 SQLite에 저장한다.
- **MOB-ENC-009**: 채집하지 않은 생물 이미지는 회색, 채집한 생물 이미지는 원래 색상으로 표시한다.
- **MOB-ENC-010**: 현재 필터 결과에 대해 카테고리별 상태를 전체 체크하거나 전체 체크 해제할 수 있어야 한다. 생물은 채집·기증, 화석은 보유·기증, 미술품은 진품 보유·가품 보유·기증을 대상으로 한다.
- **MOB-ENC-011**: 전체 체크·해제는 현재 필터 결과와 현재 활성 섬에만 적용한다.
- 월별 신규·종료 표시는 도감 목록이 아니라 오늘 화면의 현재 출현 생물 카드에서 제공한다.

## 5. 데이터 및 저장 요구사항

### 5.1 저장 방식

- 모바일 앱은 로그인 없이 기기 내 SQLite를 사용한다.
- 저장소의 `dataset/app-ready/`를 기준 데이터 입력 원본으로 사용한다.
- 빌드 전에 앱에서 사용하는 `content/`와 `assets/`만 `acnh-diary-mobile/src/data/` 아래로 복사·검증해 번들한다. 앱 런타임이 저장소의 `seed/`를 직접 읽지 않는다.
- 원본 출처는 ACNHAPI, Norviah, Nookipedia 등 파일별 출처 메타데이터로 관리하며, 특정 단일 API를 런타임 의존성으로 두지 않는다.
- 주민 기준 데이터는 추가 26명을 포함한 총 417명을 제공해야 하며, 주민 키는 `villager_id` 문자열을 사용한다.
- 주민 원천 데이터에서 현재 417명 모두 활동 시간과 하우스 가구 목록이 비어 있으므로, 앱은 해당 값을 추정하지 않고 값이 있을 때만 표시한다. 하우스 외관·내부 이미지와 벽지·바닥·음악은 제공된 기준 데이터를 사용한다.
- 사용자 기록은 기준 데이터와 별도 테이블에 저장한다.
- 웹앱과 모바일앱 사이의 자동 동기화는 제공하지 않는다.
- 앱 삭제나 기기 변경에 대비해 모바일 첫 출시부터 수동 백업·복원을 제공한다.

### 5.2 섬별 격리

모든 루틴, 루틴 로그, 주민 상태, 캠핑장 방문, NPC 방문, 도감 수집 기록은 `islandId`를 필수로 가진다. 섬 변경 시 현재 화면과 캐시를 모두 새 섬 기준으로 교체한다.

### 5.3 백업·복원

- 전체 섬과 사용자 기록을 버전 포함 JSON 파일로 내보낸다.
- 백업 파일에는 `schemaVersion`, `appVersion`, `exportedAt`, `dataVersion`, `islands`, `profiles`, `routines`, `routineLogs`, `collectionRecords`, `villagerStates`, `residencies`, `campsiteVisits`, `npcVisits`, `appSettings`를 포함한다. `appSettings.manual_game_date`는 수동 날짜가 없을 때 `null`로 저장한다.
- 가져오기 전에 JSON 형식, 스키마 버전, 중복 ID, 외래키 관계를 검증한다.
- 복원은 기존 로컬 데이터 교체 여부를 확인한 후 하나의 SQLite 트랜잭션으로 수행한다.
- 복원 실패 시 전체 rollback하고 기존 데이터를 유지한다.
- 향후 스키마 버전은 migration으로 이전 백업과 호환할 수 있어야 한다.

## 6. 비기능 요구사항

- **NFR-MOB-001 반응성**: 일반적인 모바일 기기에서 목록 스크롤과 상태 토글이 끊김 없이 동작해야 한다.
- **NFR-MOB-002 오프라인**: 네트워크가 없어도 오늘·주민·도감의 기준 데이터 조회와 사용자 기록 변경이 가능해야 한다.
- **NFR-MOB-003 영속성**: 앱을 종료·재실행해도 저장된 섬과 사용자 기록이 유지되어야 한다.
- **NFR-MOB-004 접근성**: 상태 아이콘에 접근성 레이블을 제공하고, 색상 외의 상태 표현을 제공해야 한다.
- **NFR-MOB-005 성능**: 첫 유효 화면 표시 목표는 일반 기기에서 2초 이내로 측정한다.
- **NFR-MOB-006 데이터 보호**: 백업 파일 공유·삭제·복원에는 사용자 확인을 요구한다.
- **NFR-MOB-007 호환성**: 현재 출시 검증 대상의 최소 지원 OS는 iOS 16.0+로 한다. Android 9.0(API 28+) 지원은 후속 플랫폼 단계에서 검증한다.
- **NFR-MOB-008 출처 고지**: `설정 → 앱 정보 → 데이터 출처 및 라이선스`에서 기준 데이터별 원 출처·이용 조건 링크, 기준 데이터 버전·갱신일, 오픈소스 라이선스를 표시한다.
- **NFR-MOB-009 데이터 누락 처리**: 기준 데이터에 없는 활동 시간·하우스 가구·캘린더 이벤트·NPC 이미지는 임의로 생성하지 않는다. 값이 없는 상세 행은 숨기고, NPC 이미지는 이름을 보존하는 접근성 가능한 fallback을 사용한다.
- **NFR-MOB-010 UI 일관성**: 둥근 형태와 파스텔 계열 디자인 토큰을 사용하되 텍스트와 아이콘의 대비를 확보한다.
- **NFR-MOB-011 iOS 빌드 기준**: 현재 출시 검증은 Expo SDK 57·React Native 0.86.3·Xcode 16.1 이상 조합을 기준으로 하며, 저장소에서 Xcode 26.3 빌드를 확인했다. Xcode 26 계열에서 필요한 `expo-modules-jsi` 호환성 패치는 저장소의 `patches/`에서 재현 가능해야 한다.

## 7. 오류 및 예외 요구사항

- 기준 데이터가 없으면 빈 상태와 데이터 버전 확인 안내를 제공한다.
- 검색 결과가 없으면 검색어 수정과 필터 초기화 행동을 제공한다.
- SQLite 저장 실패 시 변경되지 않았음을 알리고 재시도할 수 있어야 한다.
- 잘못된 백업 파일은 원본 데이터를 변경하지 않고 오류 원인을 표시한다.
- 지원하지 않는 백업 스키마 버전은 복원하지 않고 업데이트 안내를 표시한다.
- 마지막 섬 삭제와 존재하지 않는 주민·아이템 상태 변경은 차단한다.
- 기준 데이터에 특정 상세 필드가 없으면 해당 필드를 숨긴다.
- 데이터 버전 갱신 실패가 기존 기준 데이터와 사용자 기록 사용을 막아서는 안 된다.

## 8. 수용 기준

- 최초 실행에서 섬과 주민대표를 등록하고 오늘 화면으로 이동한다.
- 여러 섬을 만든 뒤 섬을 바꾸면 개인 기록이 섬별로 정확히 바뀐다.
- 오전 4:59와 5:00의 게임 날짜가 올바르게 달라진다.
- 수동 날짜가 자동 날짜보다 우선하고 해제 시 자동 날짜로 돌아간다.
- 루틴 완료 상태가 회색·원색 이미지와 체크 상태에 일치한다.
- 루틴 정의를 수정·삭제해도 과거 날짜의 로그가 사라지지 않는다.
- 주민의 복수 상태와 캠핑장 복수 방문일이 유지된다.
- 도감 필터 칩을 복수 선택해 조합할 수 있다.
- 도감 카드의 카테고리별 상태 아이콘 변경이 상세 화면과 목록에 즉시 반영된다. 생물은 채집·기증, 화석은 보유·기증, 미술품은 진품·가품·기증을 사용한다.
- 도감 전체 체크·해제가 현재 필터 결과와 활성 섬에만 적용된다.
- 오늘 화면의 현재 출현 생물에 월별 신규·종료 표시가 반구와 월 순환 규칙에 맞게 표시된다.
- 액자 사진 보유 변경이 주민 액자 상태에 반영된다.
- 백업을 내보낸 후 데이터를 변경하고 복원하면 백업 시점의 기록으로 돌아간다.
- 잘못된 백업 복원 실패 시 기존 기록이 보존된다.
- 앱 정보 화면에서 데이터 출처와 라이선스 고지를 확인할 수 있다.
- 카탈로그 대분류·소분류가 정의된 순서로 열리고 선택한 범위 밖의 아이템은 표시되지 않는다.
- 태블릿 카탈로그 목록은 두 열, 모바일 목록은 한 열로 표시된다.
- 레시피 재료·시즌·이벤트·재료별 필터와 사진/포스터 독립 보유 상태가 유지된다.

## 9. 개발 단계

### Phase 0 · 실행 기준선

- 프로젝트 루트는 저장소의 `acnh-diary-mobile/`이다.
- 패키지 관리자는 npm이며 `package-lock.json`을 기준으로 `npm ci --legacy-peer-deps`를 수행한다.
- Expo SDK 57과 호환되는 패키지만 `npx expo install`로 추가한다.
- `npx tsc --noEmit`과 `npx expo config --json`이 통과해야 한다.
- 개발 서버 확인은 `npx expo start --offline`으로 수행한다.
- iOS는 지원되는 Xcode로 `npx expo run:ios`를 확인한다.
- Android 네이티브 빌드는 현재 수용 기준에서 제외하고 후속 플랫폼 단계에서 확인한다.
- 웹은 최초 출시 플랫폼이 아니므로 `npm run web`을 모바일 빌드의 수용 기준으로 사용하지 않는다.

Phase 0의 완료 기준은 스플래시 → 온보딩 → 오늘 화면의 이동, SQLite 초기화, 앱 재실행 시 섬 존재 여부 복원, iOS 개발 빌드 실행이다. Android 빌드는 후속 플랫폼 단계에서 추가한다.

### Phase 1 · 공통 기반

TypeScript 도메인 타입·정책, 주민·박물관 기준 데이터 adapter, 앱용 데이터 복사·검증 스크립트, SQLite migration v1, Repository 계약과 테스트 실행 기반, 디자인 토큰

### Phase 2 · 모바일 MVP 핵심

온보딩·섬 관리, 오늘, 주민, 도감, 카탈로그, 독립 상세 화면, 오프라인 저장, 상태 일괄 변경

### Phase 3 · 모바일 출시 준비

JSON 백업·복원, 앱 정보·라이선스 화면, 접근성·성능·기기 호환성 검증, 스토어 빌드

### Phase 4 · 후속 확장

카탈로그 변형별 수집, 공략, 날씨, 무값 계산기, 통계

## 10. 결정 및 미정 관리

### 10.1 확정

- 모바일은 React Native + Expo + TypeScript + SQLite 로컬 우선
- 라우팅은 Expo Router를 사용하고 `src/app`을 공식 화면 루트로 사용
- 로그인·서버·웹·모바일 자동 동기화 없음
- 하단 탭은 오늘·주민·도감·카탈로그·공략
- MVP 핵심은 오늘·주민·도감·카탈로그
- 기준 데이터 입력 원본은 `dataset/app-ready/`이며 ACNHAPI·Norviah·Nookipedia 등 파일별 출처를 보존
- 앱 번들 기준 데이터는 Phase 1에서 검증된 파일 목록만 `acnh-diary-mobile/src/data/`로 복사하며, `seed/`와 원본 저장소 경로는 런타임에서 직접 읽지 않음
- 도감 필터는 복수 선택 가능한 칩
- 화석 정렬은 기준 데이터에 번호가 있을 때 번호·이름·화석 그룹을 사용하고, 번호가 없으면 이름·화석 그룹을 사용
- 사진·포스터는 액자 사진과 포스터 탭으로 분리
- 액자 사진 보유와 주민 액자 상태를 연동
- 루틴 정의 변경은 오늘 이후 적용하고 과거 기록 보존
- 모바일 첫 출시부터 버전 포함 JSON 백업·복원 제공
- 앱 정보 화면과 앱 스토어에 출처·라이선스 표시
- 도메인 내부의 반구 값은 `north`/`south`, 시간대 값은 IANA time zone 문자열을 사용하고 화면 표시명은 별도 라벨 맵으로 변환
- `app_settings.manual_game_date`가 `null`이면 기기 시각과 게임 날짜 경계를 사용

### 10.2 세부 확정 사항

- 도감 원본 필드명과 각 원천 데이터의 원문 키는 내부 데이터에서 유지하고, 사용자 화면 표시명은 별도 UI 라벨 맵 JSON으로 관리한다. 최초 출시 기준은 한국어를 기본으로 하며, 이후 영어 locale 확장을 위해 동일한 키 구조를 재사용한다.
- 현재 iOS 최소 지원 OS 버전은 iOS 16.0+로 설정한다. Android 9.0(API 28+) 지원은 후속 플랫폼 단계에서 별도로 확정한다.
